# Backup Everything

Личное macOS-приложение для бэкапов. Спецификация поведения: `docs/superpowers/specs/2026-09-30-backup-manager-design.md`; хранение копий (rsync, защищённые назначения) описано в `docs/superpowers/specs/2026-10-07-storage-rework-design.md`. Спецификации нужно обновлять вместе с каждым изменением поведения.

- `BackupCore/` — ядро без UI (Swift Package, macOS 14+).
- `App/` — приложение на SwiftUI (исполняемый таргет `BackupEverything`, macOS 15+). Зависит от ядра, ядро от него — нет.
- `scripts/build-app.sh` — сборка `.app`.
- `scripts/setup-storage.sh` — установка хранилища: служебная учётка, шлюз, правило sudo, права на назначения (запускается под `sudo`, см. «Установка хранилища»).
- `docs/mockups/` — HTML-макеты вариантов интерфейса.

## Сборка

Нужны Xcode 16+, утилита `trash` (`brew install trash`) и rsync 3 из Homebrew (`brew install rsync`): копии пишет он, системный rsync 2.6.9 не подходит.

```bash
./scripts/build-app.sh
```

Скрипт собирает релиз, подписывает его и кладёт в `dist/BackupEverything.app`. Подпись — сертификатом «Backup Everything Local» из Связки ключей (самоподписанный, тип «Подпись кода»), чтобы macOS помнила разрешения между сборками; если его нет — ad-hoc, и разрешения спрашиваются после каждой сборки. Предыдущая сборка уходит в Корзину. Папка `dist/` в git не хранится: после клонирования приложение нужно собрать заново.

Запуск:

```bash
open dist/BackupEverything.app
```

## Тесты

```bash
swift test --package-path BackupCore
swift test --package-path App
```

Перед коммитом обязательны оба прогона и успешная сборка. Проверять код возврата каждой команды: цепочка через `;` не остановится на упавшей сборке.

## Установка хранилища

Копии лежат в папках, которые принадлежат служебной учётке `_backupeverything`; приложение работает от Макса и не может удалить или изменить их (подробно — в спеке хранения). Записывает копии rsync-получатель от этой учётки через шлюз `backup-receiver` по правилу sudo без пароля.

```bash
sudo scripts/setup-storage.sh
```

Скрипт создаёт учётку, собирает и ставит шлюз в `/usr/local/libexec/backup-everything/`, пишет правило в `/etc/sudoers.d/backup-everything` (с SHA-256 шлюза), а для каждого назначения из `config.json` (только корни в `/Volumes/<диск>/…` или внутри домашней папки) включает учёт владельцев на внешнем диске, снимает пользовательские замки, ставит метку `.complete` на копиях прежней версии, передаёт папку учётке (`chown -R _backupeverything:staff`) и открывает её на чтение группе (`chmod -R g+rX`), чтобы Макс читал копии. Пока запущено приложение, скрипт не работает. Он печатает каждую команду; `--dry-run` только печатает. Запускать его можно из любого места, но только после согласования с Максом: он меняет системные настройки и владельца папок с копиями. Повторный запуск нужен при новом назначении и после пересборки шлюза. Чтобы он читал настройки песочницы (`$BACKUP_EVERYTHING_HOME/data/config.json`), переменная передаётся через sudo: `sudo BACKUP_EVERYTHING_HOME=… scripts/setup-storage.sh`.

Чего не хватает установке, приложение показывает в полосе “Setup” раздела “Destinations”.

## Прод не должен потеряться

Прод — это приложение, которым Макс пользуется каждый день, и его данные:

- запущенное `dist/BackupEverything.app` (bundle id `local.backup-everything`);
- `~/BackupEverything/` — `config.json`, `state.json`, `history/`, `templates/`, `icons/`;
- `~/Library/Application Support/BackupEverything/` — рабочие файлы;
- сами копии в назначениях.

Правила:

1. Не завершать и не перезапускать прод-приложение без явного согласия Макса, и никогда — пока идёт бэкап. При перезапуске теряются несохранённые правки в окне. После сборки отдать команду запуска, а не запускать самому.
2. `scripts/build-app.sh` заменяет `dist/BackupEverything.app`. Запускать его только когда новая версия готова к тому, чтобы стать продом: тесты зелёные, поведение проверено в песочнице.
3. Перед любой правкой файлов в `~/BackupEverything/` сделать копию изменяемого файла. Править точечно, сохраняя всё, что Макс настроил сам (например, список игнорируемых репозиториев в команде GitHub).
4. Копии в назначениях не трогать. Приложение не умеет удалять копии; команды из раздела “Excess copies” (копии сверх правила хранения) выполняет только Макс.
5. Встроенные шаблоны записываются в `~/BackupEverything/templates/` только если файла ещё нет. Поменялся шаблон в коде — обновить и файл у Макса, и уже созданный из него источник в `config.json`.
6. Удалять что угодно только через `trash`.

## Песочница

Все эксперименты и проверки интерфейса — на отдельной копии с отдельными данными, прод при этом продолжает работать:

```bash
swift build -c release --package-path App
```

Собранный бинарник положить в отдельный `.app` вне `dist/`, в его `Info.plist` поменять `CFBundleIdentifier` на `local.backup-everything.sandbox` и запустить с переменной `BACKUP_EVERYTHING_HOME`, указывающей на временную папку: в ней окажутся и настройки, и рабочие файлы. Флаг `--show-window` сразу открывает окно.

Песочница пишет копии обычным rsync, без шлюза и служебной учётки: для этого запускать с `BACKUP_EVERYTHING_DIRECT_RSYNC=1`. Только вместе с `BACKUP_EVERYTHING_HOME` на временную папку (без неё приложение переменную не замечает) и назначениями во временных папках; с настоящими настройками эту переменную не задавать никогда: защиты копий в этом режиме нет.

Открытый раздел и выбранные элементы песочницы задаются через `defaults write local.backup-everything.sandbox` (`section`, `selectedSource`, `selectedDestination`).

Снимки экрана делать только с окна песочницы, не со всего экрана.

## Секреты

В `config.json` и в репозитории секретов нет и быть не должно: команды берут их из Связки ключей или из собственной авторизации утилит (`bw`, `gh`). Пароли Макс вводит сам. Содержимое экспортов с паролями не открывать.
