# Backup Everything

Личное macOS-приложение для бэкапов. Спецификация поведения: `docs/superpowers/specs/2026-09-30-backup-manager-design.md`; хранение копий (rsync, защищённые назначения) описано в `docs/superpowers/specs/2026-10-07-storage-rework-design.md`. Спецификации нужно обновлять вместе с каждым изменением поведения.

- `BackupCore/` — ядро без UI (Swift Package, macOS 14+). Там же шлюз: цель `backup-receiver` (`Sources/backup-receiver/main.swift`) поверх библиотеки `ReceiverGate` (`Gate` разбирает и проверяет аргументы, `Claimer` атомарно занимает папку копии или метку).
- `App/` — приложение на SwiftUI (исполняемый таргет `BackupEverything`, macOS 15+). Зависит от ядра, ядро от него — нет.
- `scripts/build-app.sh` — сборка `.app`.
- `scripts/setup-storage.sh` — установка хранилища: служебная учётка, шлюз, правило sudo, права на назначения (запускается под `sudo`, см. «Установка хранилища»). В сборке лежит в `Contents/Resources/`.
- `docs/mockups/` — HTML-макеты вариантов интерфейса.

## Сборка

Нужны Xcode 16+, утилита `trash` (`brew install trash`) и rsync 3 из Homebrew (`brew install rsync`): копии пишет он, системный rsync 2.6.9 не подходит.

```bash
./scripts/build-app.sh
```

Скрипт собирает релиз приложения и шлюза `backup-receiver` (в `Contents/Helpers/`), кладёт рядом скрипт установки (`Contents/Resources/setup-storage.sh`), подписывает бандл и кладёт в `dist/BackupEverything.app`. Подпись — сертификатом «Backup Everything Local» из Связки ключей (самоподписанный, тип «Подпись кода»), чтобы macOS помнила разрешения между сборками; если его нет — ad-hoc, и разрешения спрашиваются после каждой сборки. Предыдущая сборка уходит в Корзину. Папка `dist/` в git не хранится: после клонирования приложение нужно собрать заново.

Запуск:

```bash
open dist/BackupEverything.app
```

## Тесты

```bash
swift test --package-path BackupCore
swift test --package-path App
```

Перед коммитом обязательны оба прогона и успешная сборка. Проверять код возврата каждой команды: цепочка через `;` не остановится на упавшей сборке.

## Установка хранилища

Копии лежат в папках, которые принадлежат служебной учётке `_backupeverything`; приложение работает от Макса и не может удалить или изменить их (подробно — в спеке хранения). Записывает копии rsync-получатель от этой учётки через шлюз `backup-receiver` по правилу sudo без пароля.

```bash
sudo dist/BackupEverything.app/Contents/Resources/setup-storage.sh "<папка назначения>"
sudo dist/BackupEverything.app/Contents/Resources/setup-storage.sh --undo "<папка>"
sudo dist/BackupEverything.app/Contents/Resources/setup-storage.sh --uninstall
```

Скрипт и шлюз лежат в собранном приложении; из репозитория (`scripts/setup-storage.sh`) скрипт берёт шлюз из `BackupCore/.build/release/`, сам ничего не собирает. Пять шагов, перед каждым — что произойдёт, точные команды и вопрос `Run? [y/N]`: учётка `_backupeverything` (UID 450–499), шлюз в `/usr/local/libexec/backup-everything/`, правило в `/etc/sudoers.d/backup-everything` (без SHA-256: путь принадлежит root), `diskutil enableOwnership` на внешнем диске, `chown` папки на учётку (не рекурсивно, если папка пуста; иначе по порядку `chflags -R nouchg,nouappnd`, `chmod -R g+rX,go-w`, `chmod -R -N`, `chown -R` последним, о чём шаг предупреждает отдельно; повторный запуск чинит прерванную передачу), `chmod 750` и `chmod -N` папки, затем проверка от имени учётки, что она до папки доходит (папка внутри Desktop, Documents, Downloads и других папок `700` не подходит). Папка должна существовать: её создаёт Макс или приложение, не скрипт. Данные в ней (старые копии, ручные бэкапы, диск с другого Mac) переносить не нужно: они остаются под защитой. Папка `<slug>/<дата>/` с пустым файлом `.complete` — полноценная копия, откуда бы она ни взялась (спека хранения, 8); без `.complete` она показывается как незавершённая попытка; и те и другие служат `--link-dest`, так что уже сделанные копии не копируются заново. `--undo` возвращает папку со всем содержимым Максу, `--uninstall` убирает правило, шлюз и учётку. Права копий (750/640) ставит шлюз своим `umask 027`. Согласие на шаг — `y`, `Y` или `yes`. Шлюз ставится, только если `/usr/local` и `/usr/local/libexec` принадлежат root (иначе правило sudo было бы небезопасным).

Allow-list шлюза привязан к буквам, которые шлёт получателю rsync 3.5.1. После `brew upgrade rsync` каждая копия может громко падать с “refused option …”, пока шлюз не обновят под новый rsync; это намеренное поведение (шлюз закрыт по умолчанию), а не поломка. Запускать скрипт только после согласования с Максом: он меняет системные настройки и владельца папки с копиями. Повторный запуск нужен на каждое новое назначение и после пересборки шлюза.

Какой папке чего не хватает, приложение показывает в полосе “Setup” раздела “Destinations” вместе с готовой командой. Проверить правило sudo руками:

```bash
sudo -u _backupeverything /usr/local/libexec/backup-everything/backup-receiver --check
```

Копии прошлой версии приложения (с `_snapshot.json` внутри) становятся копиями после расстановки меток; команда из спеки хранения (8), выполняется под `sudo`, когда папка уже передана учётке:

```bash
sudo find "<папка назначения>" -mindepth 2 -maxdepth 2 -type d -name '20*' -exec sh -c '[ -e "$1/_snapshot.json" ] && [ ! -e "$1/_unfinished" ] && touch "$1/.complete"' _ {} \;
```

Finder и `sudo` могут менять и удалять копии после ввода пароля администратора: это сознательное действие Макса, оно задумано так. Приложение пароль спросить не может, других правил sudo у него нет.

### Что установлено у Макса

Хранилище переведено на новую схему 2026-10-18: учётка `_backupeverything` (UID 450), шлюз и правило sudo стоят, назначение “Laptop folder” (`~/Files/BackupsTest`) передано учётке, старые копии помечены `.complete`, новые копии пишутся через шлюз. Назначение “HDD” (`/Volumes/MAX'S HDD/Backups`) ещё не передано: когда диск подключён, выполнить команду из полосы “Setup” и команду расстановки меток выше. Остаточная учётка `_betest` от испытаний не нужна: `sudo sysadminctl -deleteUser _betest` после согласования.

## Прод не должен потеряться

Прод — это приложение, которым Макс пользуется каждый день, и его данные:

- запущенное `dist/BackupEverything.app` (bundle id `local.backup-everything`);
- `~/BackupEverything/` — `config.json` (схема 3), `state.json` (схема 2), `history/`, `templates/`, `icons/`. Перед первой записью в новом формате старый файл настроек остаётся рядом как `config.v<N>.json`: с ним можно вернуться на прошлую версию приложения. Копии данных до перехода на новое хранение лежат в `before-storage-rework/`;
- `~/Library/Application Support/BackupEverything/` — рабочие файлы: `pending/` (пакеты для назначений, которых не было на связи), `staging/`, `chains/`, `scratch/`;
- сами копии в назначениях.

Правила:

1. Не завершать и не перезапускать прод-приложение без явного согласия Макса, и никогда — пока идёт бэкап. При перезапуске теряются несохранённые правки в окне. После сборки отдать команду запуска, а не запускать самому.
2. `scripts/build-app.sh` заменяет `dist/BackupEverything.app`. Запускать его только когда новая версия готова к тому, чтобы стать продом: тесты зелёные, поведение проверено в песочнице.
3. Перед любой правкой файлов в `~/BackupEverything/` сделать копию изменяемого файла. Править точечно, сохраняя всё, что Макс настроил сам (например, список игнорируемых репозиториев в команде GitHub).
4. Копии в назначениях не трогать. Приложение не умеет удалять копии; команды из раздела “Excess copies” (копии сверх правила хранения) выполняет только Макс.
5. Встроенные шаблоны записываются в `~/BackupEverything/templates/` только если файла ещё нет. Поменялся шаблон в коде — обновить и файл у Макса, и уже созданный из него источник в `config.json`.
6. Удалять что угодно только через `trash`.

## Известные проблемы

- Два теста ядра изредка падают под нагрузкой: `UndecodableNameTests.listingNamesTheFolder` и `ProcessRunnerTests.stopsProcessOnTimeout`. Это блокер, который нужно починить, а не перезапустить.
- В `state.json`, перенесённом из первой версии хранения, у назначений могут остаться старые `lastError` и `retryAfter` (в Overview — “The destination is out of space”). Они уходят после первого успешного прогона; чистка при миграции не сделана.

## Песочница

Все эксперименты и проверки интерфейса — на отдельной копии с отдельными данными, прод при этом продолжает работать:

```bash
swift build -c release --package-path App
```

Собранный бинарник положить в отдельный `.app` вне `dist/`, в его `Info.plist` поменять `CFBundleIdentifier` на `local.backup-everything.sandbox` и запустить с переменной `BACKUP_EVERYTHING_HOME`, указывающей на временную папку: в ней окажутся и настройки, и рабочие файлы. Флаг `--show-window` сразу открывает окно.

Песочница пишет копии обычным rsync, без шлюза и служебной учётки: для этого запускать с `BACKUP_EVERYTHING_DIRECT_RSYNC=1`. Только вместе с `BACKUP_EVERYTHING_HOME` на временную папку (без неё приложение переменную не замечает) и назначениями во временных папках; с настоящими настройками эту переменную не задавать никогда: защиты копий в этом режиме нет.

Открытый раздел и выбранные элементы песочницы задаются через `defaults write local.backup-everything.sandbox` (`section`, `selectedSource`, `selectedDestination`).

Снимки экрана делать только с окна песочницы, не со всего экрана.

## Секреты

В `config.json` и в репозитории секретов нет и быть не должно: команды берут их из Связки ключей или из собственной авторизации утилит (`bw`, `gh`). Пароли Макс вводит сам. Содержимое экспортов с паролями не открывать.
