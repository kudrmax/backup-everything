# Backup Everything — дизайн

Дата: 2026-09-30. Статус: на ревью.

## 1. Цель

Личное macOS-приложение, которое в одном месте знает про все бэкапы Макса: что, откуда, куда, когда делалось в последний раз и что просрочено. Работает в фоне, почти не потребляет ресурсов, автоматизирует то, что можно автоматизировать, а для остального хранит инструкцию и напоминает.

Критерии успеха:

- Новый источник или назначение добавляется через UI, без правки кода.
- Один взгляд на menu bar отвечает на вопрос «всё ли в порядке с бэкапами».
- Приложение в простое не нагружает систему: нет опроса диска, нет постоянных таймеров.
- Бэкап либо записан целиком, либо не существует. Последняя успешная копия не теряется никогда.
- Все данные приложения лежат в одной читаемой папке, которая бэкапится как обычный источник.

## 2. Что сказал Макс и что решено

Сказано Максом:

- Источники: парольник (сейчас Bitwarden, позже «Пароли» macOS), iOS-приложение финансов (CSV), Google Photos, Obsidian, GitHub (все репозитории или список), Claude.
- Назначения: внешний HDD, папка на диске, облако.
- Иконка в menu bar и полноценное окно.
- Хранение версий с увеличивающимися интервалами (GFS).
- Для ручных экспортов: оригинал после подхвата удалять или оставлять — настройка на источник, по умолчанию удалять.
- Облако через rclone сразу в MVP.
- Шифрования в MVP нет, добавится позже.
- В MVP для неавтоматизируемых источников достаточно инструкции, заданной при создании источника.
- Экспорт Claude отдаёт не архив, а манифест со ссылками на архивы. Для таких источников нужен полуавтоматический тип: последовательность шагов, где одни делает человек, а другие — команда в терминале. В копию Claude попадают только архивы, манифест не нужен.
- Файлы в «Загрузках» узнаются по именам. Переименование загрузок в браузере (Arc) Макс отключает.

Решено при проектировании:

- Стек: Swift + SwiftUI, один процесс, macOS 14+.
- Источник — это список шагов (папка, команда, файл от человека, подключить устройство); типов источника нет. Два типа назначений. Этого хватает на весь список и на комбинации вроде «подключить устройство → команда → папка».
- Шаблоны источников лежат файлами и добавляются без кода.
- Интерфейс на русском.

## 3. Границы MVP

Входит:

- Источники из шагов четырёх видов: «Скопировать папку», «Выполнить команду», «Получить файл от тебя», «Подключить устройство».
- Назначения типов «Локальная папка» (в том числе внешний диск) и «Rclone».
- Расписание на источник, хранение по GFS с превью, догон недоступных назначений.
- Menu bar, окно с разделами «Обзор», «Источники», «Назначения», «История», «Настройки».
- Уведомления, автозапуск при входе.
- Шаблоны источников: GitHub, Obsidian, Bitwarden, Google Photos, Claude, Claude Code, Пароли macOS, iOS-финансы.
- Источник «Настройки Backup Everything», создаваемый при первом запуске.

Не входит:

- Шифрование.
- Мастер восстановления (есть только «Показать в Finder» и «Открыть в облаке»).
- Дедупликация неизменившихся файлов между снапшотами.
- Автоматический запуск ручных экспортов (Takeout и подобных).
- Настройка rclone remote из UI: в MVP remote создаётся в терминале по инструкции.

## 4. Модель предметной области

**Источник (Source)** — запись в конфиге:

- `id`, `name`, `steps` — список шагов, от одного и больше (4.1);
- `schedule`: `daily | weekly | monthly | manual` (только по кнопке);
- `retention`: `{daily, weekly, monthly, yearly}`;
- `destinationIds`: список назначений;
- `description`: одна-две фразы о том, что именно бэкапится (показывается под именем источника и при наведении на имя в обзоре);
- `instructions`: шаги, которые должен сделать человек (установка, вход, ручной экспорт), в Markdown; показывается в UI и в уведомлениях. Описание и инструкция — разные поля, шаблон задаёт оба;
- `icon`: необязательный значок — имя PNG-файла в `icons/`. Любой значок источника (свой или системный) рисуется на полупрозрачной серой плитке со скруглением, чтобы ряд был ровным. Любая выбранная картинка приводится к PNG 128×128; файлы, на которые не ссылается ни один источник, удаляются;
- `enabled`.

**Назначение (Destination)**: `id`, `name`, `type`, параметры типа, `expectedEvery` — как часто назначение обязано быть доступным: `always` (по умолчанию для облака и папки на внутреннем диске) или интервал «не реже чем раз в N дней» (для внешнего диска, например 30).

**Снапшот (Snapshot)** — одна версия одного источника в одном назначении. Идентифицируется временем сбора данных.

**Прогон (Run)** — одна попытка забэкапить источник: время, результат по каждому назначению, текст ошибки, размер.

**Долг (Debt)** — пара «источник, назначение», для которой бэкап не доставлен, потому что назначение было недоступно или запись упала.

### 4.1. Шаги источника

Типов источника нет. У источника есть расписание, назначения, хранение и список шагов, которые выполняются по очереди. Видов шагов четыре:

| Шаг | Кто делает | Параметры | Что даёт копии |
|---|---|---|---|
| Скопировать папку | приложение | `path` (папка или файл), `excludes` (glob) | содержимое папки |
| Выполнить команду | приложение | `command`, `timeoutSeconds` | то, что команда положила в `BACKUP_OUTPUT_DIR` |
| Получить файл от тебя | человек, приложение ждёт | `instructions`, `watchPath`, `filePattern` (glob), `fileMode` (`single` или `multiple`), `includeInCopy`, `removeOriginal` | файлы, если `includeInCopy`; иначе они лежат в `BACKUP_INPUT_DIR` для следующих команд |
| Подключить устройство | человек, приложение ждёт | `instructions`, `path` | ничего: шаг ждёт, пока путь появится (устройство подключено) |

**Что попадает в копию.** Источник из одного шага «Скопировать папку» отдаёт папку как есть, без промежуточной копии. В остальных случаях шаги работают в рабочих папках запуска (`BACKUP_INPUT_DIR`, `BACKUP_OUTPUT_DIR`, `BACKUP_SCRATCH_DIR`, общие для всех шагов), и копией становится `BACKUP_OUTPUT_DIR`. Пустой результат — ошибка, снапшот не создаётся.

**Источник без шагов человека** (только папки и команды) запускается по расписанию или кнопкой «Запустить» и при каждом запуске, включая догон, собирает копию заново.

**Источник с шагом человека** (файл или устройство):

- Шаг человека в начале источника ждёт, только когда источник его ждёт: подошёл срок по расписанию (то же, что автоматическое нажатие «Запустить») или нажата «Запустить». Пока источник не ждёт, приложение папки и устройства не трогает. У источника «Только вручную» ожидание включается только кнопкой. Шаг человека после автоматических шагов ждёт сам: запуск уже идёт.
- Пока ждёт шаг, начатый сроком, источник жёлтый: «пора сделать экспорт» (файл) или «пора подключить» (устройство), и раз в сутки приходит напоминание. Начатый кнопкой — спокойное «ждёт файл» / «ждёт подключения» без напоминаний; такое ожидание можно отменить кнопкой «Отменить: больше не ждать» (собранное в запуске уходит в Корзину). Ожидание по сроку не отменяется: это напоминание, оно держится до бэкапа.
- Положение запуска хранится в `state.json` (`chain`: номер и `id` шага, кто начал) и переживает перезапуск приложения; прерванная команда запускается заново с начала своего шага. Если шаги отредактировали так, что на текущем месте оказался другой шаг, запуск начинается заново, собранное уходит в Корзину.
- Результат последнего шага переносится в `pending` и доставляется оттуда: долг каждому назначению записывается до начала доставки, догон идёт из `pending`, пакет уходит из `pending` после доставки во все назначения (в Корзину, если его составляют забранные у человека файлы с `removeOriginal`, иначе удаляется). Устройство поэтому читается один раз, и догон на отключённый ранее диск не требует подключать устройство снова.
- Если в источнике есть шаг «Подключить устройство», сразу после того как результат лёг в `pending` (до доставки в назначения), приходит уведомление «Можно отключать».
- «Сделать все бэкапы заново» запускает источник с шагом человека, только если его первый шаг не придётся ждать: папка, команда или уже подключённое устройство. Ожидание файла не включает.

**Шаг «Получить файл от тебя»:**

- Файлы с расширениями незавершённой загрузки (`.crdownload`, `.download`, `.part`, `.tmp`) и пустые файлы не подхватываются. Пока в папке есть любая незавершённая загрузка или подходящий файл менялся меньше 5 секунд назад, подхват откладывается. Браузеры называют недокачанные файлы по-разному, поэтому сопоставления по имени нет.
- Первый шаг берёт файлы новее последнего подхвата этого источника (или его создания) — в том числе скачанные до нажатия кнопки. Шаг в середине — файлы, появившиеся после предыдущего шага.
- `fileMode = single`: как только файл полностью скачан, он забирается сам. `fileMode = multiple` (многотомный Takeout): найденное показывается — «N файлов · размер» с кнопкой «Забрать» — и забирается по кнопке (или «Повторить шаг»). Кнопка недоступна, пока идёт загрузка; после неудачного подхвата она остаётся рядом с ошибкой.
- Подхват атомарный: если хотя бы один файл забрать не удалось, все остаются на месте, шаг получает ошибку «Не удалось забрать файлы».
- `removeOriginal = true` (по умолчанию): файл перемещается; иначе копируется, а оригинал остаётся. Тот же файл второй раз не забирается.
- Если файл найден, но в папке есть незавершённая загрузка, источник показывает «N файлов · размер · идёт загрузка».
- Маски разных источников на одной папке не должны пересекаться. Шаблон без известного имени файла поставляется с пустой маской: пока она не задана, ничего не подхватывается.

**Шаг «Подключить устройство»:** ждёт, пока путь существует (том смонтирован). Отсутствие устройства — не ошибка. Если автоматический шаг после устройства упал, а устройства уже нет (его отключили посреди копирования), запуск возвращается к шагу устройства и снова ждёт его, без ошибки. Подключение устройства (монтирование тома) само запускает проверку, поэтому следующие шаги идут без нажатий. Если путь не задан, берётся папка следующего шага «Скопировать папку».

**Шаг «Выполнить команду»:**

- Запускается через `/bin/zsh -lc`. Ненулевой код возврата, таймаут или пустой результат — ошибка. Хвост stdout и stderr (последние 4 КБ) сохраняется в историю. По таймауту останавливается команда вместе со всеми порождёнными ею процессами. Последняя непустая строка stdout показывается как ход работы.
- Конфиг не хранит секретов. Командам, которым нужен токен или пароль, следует читать его из Keychain (`security find-generic-password`) или пользоваться собственной авторизацией инструмента (`gh auth`, `bw login`). Шаблоны так и написаны.

**Ошибка шага.** Упавший автоматический шаг убирает за собой всё, что успел добавить в копию, поэтому повтор начинается с чистого места. Источник без шагов человека повторяется через час (5.1). В источнике с шагом человека упавший шаг тоже повторяется сам через час — кроме команды, перед которой в этом источнике был шаг человека: она могла израсходовать то, что человек подготовил (одноразовые ссылки), поэтому ждёт «Повторить шаг» или «Начать заново» («Начать заново» сбрасывает запуск и сразу ждёт первый шаг). Ошибка источника из нескольких шагов называет шаг: «Шаг 2 из 3 «Скачать архивы». …».

**Старые конфиги.** До перехода на шаги у источника было поле `kind` одного из пяти типов. Такой источник читается и превращается в шаги: «Папка» → [папка], «Команда» → [команда], «Ручной экспорт» → [файл от тебя] (общая инструкция источника переезжает в шаг), «По шагам» → те же шаги (старый ручной шаг — файл, один, `removeOriginal`), «Подключаемое устройство» → [подключить устройство, папка]. `id`, `slug`, назначения не меняются; `id` новых шагов выводятся из `id` источника и одинаковы при каждом чтении. Формат `config.json` — `schemaVersion` 2; перед первой записью в новом формате прежний файл сохраняется рядом как `config.v1.json`. Старые файлы шаблонов тоже читаются.

Шаблон Claude:

1. Шаг «Получить файл от тебя» «Запросить экспорт»: claude.ai → Settings → Privacy → Export data; по ссылке из письма скачать манифест в «Загрузки». Маска `manifest-*.json`, в копию не входит.
2. Команда «Скачать архивы», таймаут 60 минут. Читает из манифеста список `data_files`. Для каждого архива: если файл с именем `filename` уже лежит в «Загрузках» и изменён позже `created_at` манифеста, он считается скачанным; иначе ссылка `export_url` открывается в браузере по умолчанию в фоне (`open -g`). Если в «Загрузках» лежит одноимённый файл старше манифеста, шаг сразу завершается ошибкой с просьбой убрать его и ни одной ссылки не открывает: иначе браузер сохранил бы новый архив под именем «… (1).zip» и шаг ждал бы его до таймаута. Файл, рядом с которым лежит `.part`, считается ещё скачивающимся. Затем команда ждёт появления архивов в «Загрузках», печатая «скачано N из M» при каждом изменении, и переносит каждый архив в `BACKUP_OUTPUT_DIR`, как только он скачан. Архив, уже лежащий в `BACKUP_OUTPUT_DIR`, считается готовым — повтор шага его ссылку не открывает. Незавершённой считается загрузка, рядом с которой лежит файл с тем же именем и расширением `.part` (Firefox), `.crdownload` (Chrome, Arc) или `.download` (Safari): такой архив не считается ни скачанным, ни старым, и его ссылка повторно не открывается. Если дождаться не удалось — ошибка со списком недостающих архивов: для недокачанных она советует дождаться загрузки или удалить прерванные файлы и повторить шаг, для остальных — запросить экспорт заново.

Ссылки экспорта одноразовые и защищены проверкой Cloudflare: без браузера (`curl`) они не скачиваются, поэтому скачивает именно браузер, в котором выполнен вход в claude.ai. После шага в браузере остаётся по вкладке на архив. Повтор шага открывает только ссылки недостающих архивов; сгоревшая ссылка лечится новым экспортом — новый манифест перезапускает цепочку.

### 4.2. Типы назначений

| Тип | Параметры | Доступность |
|---|---|---|
| Локальная папка | `path` | Путь существует и доступен на запись. Для внешнего диска это означает, что том смонтирован. |
| Rclone | `remote`, `path` | `rclone lsf remote:` завершился успешно за 15 секунд. Проверяется корень remote: папка бэкапов в облаке может ещё не существовать. |

Rclone:

- Используется установленный в системе `rclone` (поиск в `/opt/homebrew/bin`, `/usr/local/bin`, `/usr/bin`). Если его нет, раздел «Назначения» показывает инструкцию по установке.
- Используется стандартный конфиг rclone (`~/.config/rclone/rclone.conf`). Токены облаков остаются там и не попадают в папку приложения. Создание remote — по инструкции в UI через `rclone config` в терминале.
- В облако уходят только обычные файлы: символические ссылки и пустые папки не переносятся. В локальное назначение копируется всё.

### 4.3. Раскладка снапшотов

```
<корень назначения>/<slug источника>/<YYYY-MM-DD_HHmmss>/
    …содержимое…
    _snapshot.json      ← манифест, пишется последним
```

- Манифест содержит id и имя источника, время сбора, количество файлов, суммарный размер.
- Снапшот считается существующим только при наличии манифеста. Папки без манифеста — недописанные; они удаляются в начале следующего прогона в это назначение.
- Эта схема одинакова для локальной папки и rclone и не требует атомарного переименования на стороне облака.
- Файлы лежат как есть, без архивации и без проприетарного формата: снапшот открывается в Finder или в веб-интерфейсе облака без приложения.

### 4.4. Хранение (GFS)

Правило на источник: «последняя копия за каждый из N последних дней с копиями, одна в неделю за последние M недель, одна в месяц за последние K месяцев, одна в год за последние Y лет». Несколько копий за один день сворачиваются в самую свежую. Значения по умолчанию: 7 / 4 / 12 / 0.

Алгоритм (семантика restic и borg):

```
keep(snapshots, rules):
  sorted = snapshots по убыванию времени
  keepSet = { sorted[0] }                 // последняя копия живёт всегда
  для каждого уровня (day, week, month, year) с n > 0:
    seen = []
    для s в sorted:
      b = корзина(уровень, s.date)        // день | ISO-неделя | месяц | год, локальный календарь
      если b уже в seen: пропустить
      если len(seen) == n: стоп
      seen.append(b); keepSet.add(s)
  удалить snapshots \ keepSet
```

- Считаются только непустые корзины: пропущенные дни не съедают квоту.
- Применяется отдельно для каждой пары «источник, назначение» и только после успешной записи нового снапшота.
- Форма источника показывает превью: какие из существующих снапшотов останутся и какие удалятся при текущих числах.

## 5. Поведение

### 5.1. Расписание

- Источник пора бэкапить, когда `последний плановый прогон + интервал ≤ сейчас`. Источник, который ещё ни разу не запускался, пора бэкапить сразу.
- После неудачного сбора данных или неудачной записи повтор идёт не раньше чем через час — и для плановых прогонов, и для догона. Исключение — упавшая команда после шага человека: она не повторяется сама (см. 4.1).
- Планировщик держит один таймер до ближайшего срока и пересчитывает его после каждого прогона, изменения конфига, пробуждения Mac и монтирования тома. Периодического опроса нет.
- Если Mac спал в момент срока, прогон стартует после пробуждения.
- Прогоны выполняются строго по одному.

### 5.2. Один прогон

1. Источник собирает данные (папка, результат команды, подхваченный пакет или результат цепочки шагов).
2. Для каждого назначения источника:
   - доступно — удалить недописанные папки, записать снапшот, записать манифест, применить GFS;
   - недоступно или запись упала — записать долг.
3. Записать прогон в историю, обновить статус, при ошибке показать уведомление.

Сбой в одном назначении не влияет на остальные.

### 5.3. Долги и догон

- При монтировании тома, пробуждении и перед каждым плановым прогоном планировщик проверяет долги.
- Источник собирается один раз за запуск; назначение, которое запуск пропустило (было отключено, упало или добавлено позже), получает уже сделанную копию. Порядок выбора, как только должник доступен: пакет из `pending` (у источников с шагом человека); иначе самая свежая копия источника на другом доступном его назначении — переносится как есть, под тем же именем, источник заново не собирается (GitHub ничего не качает, устройство подключать не нужно; при равной дате берётся локальное назначение, облако скачивается во временную папку); иначе, если готовой копии нет нигде, источник без шагов человека собирается заново, а источник с шагом человека остаётся должен до своего следующего бэкапа (поиск копии повторяется раз в час, значок назначения в строке — «ждёт»). Пакет удаляется из `pending`, когда доставлен во все назначения.
- После догона на внешний диск приходит уведомление «Диск можно отключать».
- Назначение с интервалом `expectedEvery` («Можно не подключать до N дн») не обязано быть подключено постоянно. Каждый долг помнит, есть ли пропущенный бэкап на другом назначении источника (`elsewhere`: запуск доставил его куда-то ещё; для пропавшей копии — у источника есть копия на другом назначении; если хоть один пропущенный бэкап нигде больше нет, флаг снимается до закрытия долга). Если какого-то пропущенного бэкапа больше нигде нет (например, диск — единственное назначение источника), напоминание приходит сразу. Иначе, пока с последнего успешного догона прошло меньше интервала, долги не влияют на статус и не вызывают напоминаний; когда интервал вышел — напоминание. Оно повторяется раз в сутки. Текст: «Подключи «HDD»» + «Бэкапа «X» больше нигде нет — он запишется, как только подключишь диск» или «Диск давно не подключался. Копии есть на других дисках, но и этот пора обновить». В настройках назначения правило написано текстом под строкой срока; в подсказке значка назначения в строке источника — «копия есть на «…»» или «этого бэкапа больше нигде нет — подключи диск»; в подсказке назначения внизу обзора — что больше нигде нет или когда напомню.
- Сколько бы плановых прогонов ни было пропущено, догон создаёт один свежий снапшот на источник, а не по снапшоту за каждый пропущенный день.

### 5.3.1. Сверка с назначениями

Приложение не полагается только на собственные записи: оно проверяет, что копии действительно лежат в назначении.

- На каждом `tick()` (запуск приложения, открытие окна, пробуждение, подключение диска, плановый срок) для каждого доступного назначения проверяется, что последняя доставленная копия каждого источника на месте. Локальные назначения сверяются каждый раз, облачные — не чаще раза в сутки.
- Если копии нет, паре «источник, назначение» записывается долг, и в этом же `tick()` он закрывается по правилам догона (5.3). Приходит уведомление «Копия пропала», в «Истории» остаётся запись догона.
- Если источнику добавили новое назначение, копия туда делается сразу, не дожидаясь планового срока; уведомления «пропала» при этом нет. Поэтому после каждого сохранения настроек через пару секунд идёт `tick()`.
- Для копий, сделанных до появления сверки, последняя доставленная копия определяется по истории прогонов.
- Недоступное назначение и назначение, список копий которого не удалось получить, не сверяются: отсутствие ответа не считается пропажей.

### 5.4. Ошибки

- Недописанный снапшот не считается снапшотом (нет манифеста).
- Чистка по GFS идёт только после успешной записи нового снапшота. Снапшоты, удалённые чисткой, удаляются безвозвратно, минуя Корзину.
- Путь источника исчез или источник не дал ни одного файла — ошибка; существующие снапшоты не трогаются.
- Если корневая папка локального назначения отсутствует (диск не подключён), приложение её не создаёт и ничего не пишет по этому пути.
- В папке источника в назначении приложение удаляет только папки с именем снапшота; посторонние файлы и папки не трогает.
- Последняя успешная копия не удаляется при любых значениях правила. Только что записанный снапшот чисткой этого же прогона не удаляется никогда.
- Источник, все назначения которого удалены, считается источником без назначений: не запускается и отмечается в статусе.
- Файл настроек, который существует, но не читается, — ошибка; пустыми настройками он не подменяется.
- Нехватка места: приложение не удаляет ничего сверх правила, помечает ошибку и уведомляет.
- Ошибки в истории и уведомлениях формулируются человеческим языком с техническими деталями под спойлером.

### 5.5. Статус в menu bar

| Статус | Условие |
|---|---|
| Спокойный | Все включённые источники свежие, долгов нет. |
| Жёлтый | Источник ждёт шага человека, а запуск начат сроком («пора сделать экспорт», «пора подключить»); есть найденные файлы, ждущие «Забрать»; назначение `always` недоступно и имеет долг; у назначения с интервалом вышел срок подключения; у источника не выбрано ни одного назначения. Ожидание, начатое кнопкой («ждёт файл», «ждёт подключения»), статус не портит. |
| Красный | Последний прогон какого-либо источника завершился ошибкой, либо источник, который уже запускался, просрочен более чем на два интервала. Источник, который ещё ни разу не запускался, красным не считается: он запустится при первой возможности. |

Значок в menu bar цветной: жёлтый — нужно действие, красный — ошибка, обычный (белый/чёрный по теме) — всё в порядке. Меню по клику, сверху вниз: «Открыть окно»; блок состояния без общего заголовка — по одной строке на проблему: значок состояния (красный — ошибка, оранжевый — нужно действие), значок источника или назначения, имя и короткая причина («пора сделать экспорт», «2 файла · 23 ГБ» с кнопкой «Забрать»); ошибки идут первыми; у источника одна строка, даже если проблем несколько. Если проблем нет — «Всё в порядке · последний бэкап N назад». Клик в любое место блока открывает окно на «Обзоре», даже когда действий не нужно; «Сделать все бэкапы заново»; «Выйти». Ошибка в меню показывается одной короткой фразой (полный текст — в окне). Во время работы первой идёт строка выполняющегося источника: «GitHub · 9 из 79 · owner/repo · 4 мин». «Запускать при входе» живёт в разделе окна «Настройки».

### 5.6. Окно

- **Обзор** — один компактный список, строка на источник. В строке видно только: значок состояния, название, короткая пометка (появляется, только когда что-то не так или идёт работа), давность последнего бэкапа, когда следующий («→ через 17 ч», «→ пора», «→ по кнопке» у источников «Только вручную», «→ ждёт», пока источник ждёт файл или устройство) и значки назначений. Точное время следующего бэкапа — при наведении и в настройках источника строкой «Следующий бэкап». Подробности — при наведении. В шапке — «Обновить» (тот же `tick()`, что идёт сам по таймеру и событиям: докопировать недостающее и запустить то, чему пора; лишних бэкапов не делает) и «Сделать все бэкапы заново» (собрать всё заново и записать на все подключённые диски); то же есть в меню строки меню. Запуски доступны и во время идущего бэкапа — встают в очередь. Порядок строк выбирается в шапке: «Как в настройках» (порядок из «Источников») или «По следующему бэкапу» (ближайший и просроченный выше; без расписания и выключенные — внизу в порядке настроек); выбор запоминается. Кнопки строки появляются при наведении прямо в строке, пометка на это время укорачивается; обрезанная пометка целиком видна в подсказке. Источник, который ждёт своей очереди, помечен песочными часами и «в очереди» — в том числе сразу после «Запустить» или «Сделать все бэкапы заново», нажатых, пока идёт другой бэкап (помечаются те, что пойдут в работу, а не будут ждать файл или устройство). Пока идёт шаг без своего прогресса, пометка говорит, что он делает: «копирует файлы…» или «выполняет команду…».
- **Подсказки и кнопки во всём приложении.** Подсказка всплывает через полсекунды (следующая — сразу), пропускает мышь насквозь и исчезает при уходе курсора, клике, прокрутке или нажатии клавиши: курсор и клик под ней работают. Кнопка нажимается всей своей площадью, под курсором подсвечивается, при нажатии темнеет, выключенная — приглушена и без руки-курсора. Пункты меню в строке меню — строки во всю ширину с подсветкой; блок состояния в меню целиком открывает обзор.
  - Шапка: общий итог («Всё в порядке», «Нужно твоё действие», «N ошибок»), имя источника, который идёт сейчас, кнопка «запустить всё».
  - Пометка во время работы: «в очереди», «готовит копию…», «копирует на «имя назначения»…». Если команда источника что-то печатает в stdout, последняя непустая строка показывается как ход работы: «готовит копию · 54 из 79 · owner/repo» (шаблон GitHub печатает номер и имя репозитория). Вместо давности на время работы показывается, сколько уже идёт запуск; при наведении — сколько занял прошлый успешный запуск.
  - Пока источник в очереди или выполняется, его прежние проблемы (ошибка прошлого запуска, просрочка) не показываются и не считаются — ни в заголовке, ни в списке, ни в menu bar. Если других проблем нет, заголовок на это время — «Идёт бэкап».
  - Текст ошибки в строке — кнопка: открывает окно с полным текстом (прокрутка, выделение, «Скопировать»). При наведении показывается только подсказка, а не сам текст. То же окно доступно из «⋯ → Показать ошибку». В «Истории» у запуска с ошибкой полный текст выделяется и копируется кнопкой.
  - Пометка при проблеме: начало текста ошибки (для упавшей команды — последняя непустая строка её вывода, в ней обычно причина), «N файлов · размер» с кнопкой «Забрать», «пора сделать экспорт». Полный текст — при наведении.
  - У источника из нескольких шагов пометки о самом запуске (пора сделать экспорт, пора подключить, найденные файлы, ждёт файл, ждёт подключения, ошибка шага) начинаются с положения: «шаг 1 из 2 · пора сделать экспорт», «шаг 2 из 3 · ждёт файл», во время команды — «шаг 2 из 2 · скачано 3 из 5», при ошибке — «шаг 2 из 2 · начало текста ошибки»; остальные («не выбрано, куда бэкапить», ошибка доставки) — без положения. Те же тексты — в строке меню. Кнопки при наведении описаны ниже.
  - Значок назначения — диск или облако с меткой: зелёная галочка — последняя копия источника там есть; оранжевые часы — ещё не доставлена, назначение недоступно; красный крест — запись упала; синий пульсирующий — записывается сейчас; серый без метки — копий ещё не было. При наведении — имя назначения и время доставки.
  - Давность последнего бэкапа — это возраст самой свежей копии источника, доставленной хотя бы в одно назначение, включая догон и восстановление пропавшей копии; расписание при этом отсчитывается отдельно, от последнего планового прогона.
  - При наведении на давность — точное время последнего и следующего бэкапа и размер копии. При наведении на строку — кнопки-значки без меню «⋯»: «Запустить» (у упавшего шага — «Повторить шаг»), «Начать заново» (у цепочки, которая в процессе), «Инструкция» (если она есть), «Открыть оригинал» (у папки — открывает её в Finder), «Открыть копию» (самая свежая доставленная копия в Finder; при нескольких назначениях — выбор из списка, копия в облаке видна, но неактивна), «Изменить». Кнопки, которые ничего не сделают, не показываются. Клик по свободному месту строки открывает настройки источника; полный текст ошибки открывается кликом по самой пометке.
  - Внизу — строка назначений; текстом выделяется только требующее действия («пора подключить», «недоступно»). Назначение, которое сейчас не подключено, приглушено и помечено серым значком.
- **Источники** — два столбца в стиле обзора: слева список (значок, имя, «Добавить»: шаблоны и «Пустой — с чего начать»: «Папка», «Команда», «Файл, который выгружаешь сам», «Папка на подключаемом устройстве» — последний сразу создаёт два шага; источники переставляются перетаскиванием: брошенный встаёт на место того, на который его бросили, на «Добавить» — в конец; полоска показывает, куда встанет; этот порядок — порядок источников везде: в обзоре, меню и настройках), справа: шапка (значок — клик выбирает картинку, имя, выключатель, «⋯» с «Убрать значок» и удалением), под ней описание, затем блоки: выделенный цветом «Как часто и куда» (расписание, «Следующий бэкап», назначения-чипы), «Что делать» — карточки шагов по порядку (у источника из одного шага — без номера и стрелок; вид шага, название и поля вида; «Добавить шаг», переставить, удалить; текущий шаг запуска подсвечен), «Дополнительно» (свёрнутые «Хранить копии» и «Инструкция: как настроить один раз»). «Хранить копии» читается как история копии: «Первые 7 дней — хранятся все копии», «Потом до 4 недель — остаётся одна в неделю», «Потом до 12 месяцев — остаётся одна в месяц», «Потом до N лет — остаётся одна в год», «Потом — удаляются». Числа меняются прямо в строках; этап с нулём приглушён и подписан «не используется», история начинается с первого включённого этапа. Свёрнутая строка показывает самый дальний срок («до 12 месяцев»). Там же кнопка «Показать копии по датам». Значок источника показывается и в обзоре.
- **Назначения** — те же два столбца. В списке и шапке значок с меткой состояния (на связи, не подключено, пора подключить, недоступно), подробности при наведении. Карточка настроек: папка или облако (список remote из `rclone listremotes`), режим подключения, срок напоминания. Ниже «Копии»: занятое место и строки по источникам (число копий, возраст последней), раскрываются в список дат. Для локальных назначений при наведении на копию — «Показать в Finder»; для облака показывается имя папки снапшота (универсальной ссылки «открыть в облаке» у rclone нет).
- Планка «Отменить / Сохранить» появляется только при несохранённых изменениях (или при добавлении); в ней же показывается, чего не хватает для сохранения.
- Окно запоминает последний открытый раздел и выбранный элемент. При первом запуске (нет ни одного назначения) окно открывается само, дальше приложение живёт в menu bar.
- **История** — журнал прогонов с фильтром по источнику и результату.

### 5.7. Шаблоны

Шаблон — JSON-файл с предзаполненными полями источника (шаги, расписание, хранение, описание, инструкция). Встроенные шаблоны копируются в папку данных при первом запуске. Свой шаблон добавляется файлом в эту папку.

## 6. Данные приложения

Папка данных `~/BackupEverything/` (бэкапится источником «Настройки Backup Everything»):

```
config.json            источники и назначения
state.json             последние сборы, долги, отметки подхвата, положение в цепочках шагов
history/YYYY-MM.jsonl  прогоны, одна строка — один прогон
templates/*.json       шаблоны источников
icons/*.png            значки источников
```

Рабочая папка `~/Library/Application Support/BackupEverything/` (не бэкапится):

```
pending/<sourceId>/<timestamp>/   подхваченные, но не доставленные пакеты
chains/<sourceId>/                рабочие папки цепочки шагов: input/, output/, scratch/
staging/                          временные выходные папки команд
```

- Запись файлов состояния атомарная (временный файл и переименование).
- Рабочие папки удалённых источников (`chains/<sourceId>/`, `pending/<sourceId>/`) при следующем `tick()` уходят в Корзину.
- Файлы версионируются полем `schemaVersion`.
- Секретов в папке данных нет.

## 7. Архитектура

Два модуля:

- **`BackupCore`** — Swift Package без зависимостей от UI. Вся логика и все тесты.
- **`BackupEverythingApp`** — SwiftUI: `MenuBarExtra`, окно, уведомления, автозапуск (`SMAppService`). Читает наблюдаемое состояние ядра и вызывает его команды.

Приложение не в песочнице (запуск команд и доступ к произвольным папкам), распространяется локальной сборкой.

Компоненты ядра:

| Компонент | Ответственность | Зависит от |
|---|---|---|
| `SourceProvider` (протокол) и `FolderSource` (одна папка), `StepsSource` (автоматические шаги), `PendingSource` (результат из `pending`) | Собрать содержимое снапшота (`Payload`) и убрать за собой после прогона | `ProcessRunner`, `ManualExportInbox` |
| `ManualExportInbox` | Поиск файлов шага «Получить файл от тебя», хранение недоставленного пакета в `pending` | — |
| `StepExecutor` | Выполнить автоматический шаг (папку или команду) в рабочих папках запуска | `ProcessRunner` |
| `StepChainRunner` | Сделать один переход запуска источника с шагом человека: принять файл, дождаться устройства, выполнить автоматический шаг или собрать результат в `pending`. `BackupCoordinator` вызывает его в цикле и сохраняет состояние после каждого перехода | `ManualExportInbox`, `StepExecutor` |
| `DestinationStore` (протокол) и `LocalFolderDestination`, `RcloneDestination` | `isAvailable`, `write(payload)`, `listSnapshots`, `removeIncomplete`, `delete(snapshot)` | `ProcessRunner` |
| `RetentionPolicy` | Чистая функция: список снапшотов и правило → что оставить | — |
| `BackupEngine` | Один прогон: сбор, доставка, чистка; возвращает запись прогона | провайдеры, `RetentionPolicy` |
| `StateReducer` | Применить запись прогона к состоянию: долги, сроки, ошибки | — |
| `SchedulePlanner` | Чистые расчёты: что пора запускать, какие долги повторять, когда проснуться | — |
| `BackupCoordinator` (actor) | `tick()`: догон, подхват, плановые прогоны, напоминания; строго по одному | всё перечисленное, `TimeSource` |
| `FolderWatcher` | События файловой системы для папок шагов «Получить файл от тебя» (FSEvents) | — |
| `Store` | Чтение и атомарная запись `config`, `state`, `history`, `templates` | — |
| `StatusReporter`, `ReminderPlanner` | Сводный статус для UI и напоминания раз в сутки | `SchedulePlanner` |

Новые виды шагов добавляются в `StepKind`, `StepExecutor`/`StepChainRunner` и форму шага; новые типы назначений — реализацией протокола и регистрацией в фабрике; остальной код о конкретных типах не знает. Шифрование позже добавляется как обёртка над `DestinationStore` (или через rclone crypt) без изменений движка.

Запуск процессов и время спрятаны за протоколами `ProcessRunner` и `TimeSource`. Файловые операции не абстрагируются: тесты работают с настоящими временными папками, это надёжнее поддельной файловой системы. Состояние с конкурентным доступом изолировано актором `BackupCoordinator`.

Реализация идёт двумя планами. Первый — `BackupCore` целиком, без системных событий. Второй — приложение: таймер до ближайшего срока, события пробуждения и монтирования, `FolderWatcher`, уведомления, автозапуск и UI; все они вызывают `BackupCoordinator.tick()`.

## 8. Тестирование

Разработка через TDD.

- `RetentionPolicy` — табличные тесты: пропуски, границы недель и месяцев, нулевые правила, единственный снапшот.
- `BackupEngine` — тесты на фейковых провайдерах: успех, сбой одного назначения, недоступное назначение и долг, догон, удаление недописанных, порядок «запись, затем чистка».
- `SchedulePlanner` и `BackupCoordinator` — тесты с управляемым временем: срок, повтор через час, догон при возврате диска, одновременные `tick()`.
- `ManualExportSource` — автоподхват в режиме `single`, подхват по подтверждению в режиме `multiple`, незавершённые загрузки, старые файлы, замена пакета в `pending`.
- Долги и `expectedEvery` — статус и напоминания до и после истечения интервала, один снапшот при догоне.
- `CommandSource` — код возврата, таймаут, пустой результат (фейковый `ProcessRunner`).
- `StepChainRunner` и цепочки в `BackupCoordinator` — ручной шаг ждёт и принимает файл, `includeInCopy`, передача файлов команде, остановка на ошибке без автоповтора, «Повторить шаг», «Начать заново», перезапуск новым файлом первого шага, продолжение после перезапуска приложения, доставка и догон через `pending`.
- Команда шаблона Claude — на временной папке вместо «Загрузок» и с подменой `open`: уже скачанные архивы не открываются повторно, устаревший одноимённый файл останавливает шаг до открытия ссылок, недостающие перечислены в ошибке.
- `Store` — атомарность записи, чтение повреждённого файла, миграция `schemaVersion`.
- Интеграционные: `LocalFolderDestination` на временной папке; `RcloneDestination` на rclone-бэкенде `local`, без сети.
- UI проверяется запуском приложения вручную.
