# Неизменившиеся файлы — клоны прошлых копий: план реализации

**Goal:** В локальном назначении на APFS файл, содержимое которого уже есть в одной из прошлых копий этого источника, не записывается заново, а становится APFS-клоном. Каждая копия по-прежнему полная папка, место тратится только на новое содержимое.

**Architecture:** `LocalFolderDestination.write` делегирует запись `SnapshotWriter`. Он строит `StoredContentIndex` по манифестам прошлых копий источника (в манифесте теперь список файлов с SHA-256), для каждого файла пакета ищет копию с тем же содержимым и клонирует её через `FileCloning`, иначе копирует. Хэш записанного файла считается по самому файлу в назначении, поэтому список в манифесте всегда соответствует диску. `DestinationUsage` считает место по манифестам: одно содержимое внутри источника учитывается один раз.

**Tech Stack:** Swift 6, Swift Testing, CryptoKit (SHA-256), Darwin `clonefile(2)`.

**Spec:** `docs/superpowers/specs/2026-09-30-backup-manager-design.md`, разделы 4.3, 4.5 (новый), 8.

## Решения

1. **Клоны, а не жёсткие ссылки.** Правка файла в старой копии не портит остальные.
2. **Совпадение — по SHA-256 содержимого и размеру,** а не по имени и дате (у rsync по умолчанию — размер и mtime, что статьи на Хабре называют ненадёжным). Переименованный или перемещённый файл тоже клонируется.
3. **Ищется во всех прошлых копиях источника,** не только в последней: удалённый и вернувшийся файл не пишется заново, а учёт места остаётся точным.
4. **Кандидат проверяется перед клонированием:** файл существует, размер и время изменения совпадают с записанными в манифесте. Иначе (кто-то правил старую копию) — обычное копирование.
5. **Хэш нового файла считается по записанной копии в назначении:** если оригинал меняется во время копирования, манифест всё равно описывает то, что реально лежит на диске.
6. **Хэш файла пакета считается заранее только если в прошлых копиях есть файл такого же размера.** Для новых фото, у которых размер уникален, источник читается один раз.
7. **Клоны только если том назначения их поддерживает** (`volumeSupportsFileCloning`). Иначе — полные копии как раньше; список файлов с хэшами всё равно пишется.
8. **Сбой клонирования — не ошибка:** файл копируется.
9. **Копии старого формата** (без списка файлов) не служат источником клонов: первый бэкап после обновления пишется полностью.
10. **Облако не меняется.**
11. **Учёт места:** вне копий нового формата — как раньше, обходом; внутри — по манифестам, одно содержимое на источник один раз.

## Задачи

- [x] 1. `SnapshotManifest.files: [SnapshotFile]?`, `sharesData: Bool?`; старые манифесты читаются.
- [x] 2. `ContentHash` (SHA-256 файла потоком).
- [x] 3. `FileCloning` (протокол) и `APFSCloning` (`clonefile`, проверка тома).
- [x] 4. `StoredContentIndex` по манифестам источника, проверка кандидата.
- [x] 5. `SnapshotWriter`: клон или копия, запись списка файлов, манифест последним.
- [x] 6. `DestinationUsage` и новый `usedBytes`.
- [x] 7. Интеграционные тесты: восстановление байт-в-байт, правка клона не трогает оригинал, файл вернулся после удаления, правленая старая копия не используется, том без клонов.
- [x] 8. Спецификация, оба прогона тестов, сборка в песочнице, проверка на реальных данных в песочнице.

## Review Focus

1. Оригинал меняется во время копирования — манифест описывает записанное, а не прочитанное раньше.
2. Старую копию отредактировали руками — она не служит источником клона.
3. Удаление старой копии чисткой не затрагивает новую.
4. Недописанная копия (без манифеста) не используется как источник клонов.
